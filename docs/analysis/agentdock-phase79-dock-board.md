# AgentDock Phase 79 — Dock Board

- 작성: 2026-11-05. 기준선: `a46298a`(HEAD이자 운영 `x-agentdock-commit`).
- 표기: FACT(직접 측정), PENDING(확인 못 함). commit, push, 배포, 운영 DB 접근은 하지 않았다.

## 1. 결정

콘셉트는 "개발 도구를 발견하고 연결하는 관제실"이다. hero 오른쪽에 유형별 도크 6개가 허브 하나에 연결된 보드를 둔다.

| 안 | 3D 위치 | 모바일 | 판정 |
|---|---|---|---|
| A. Dock Board | hero 오른쪽만, 입력 없음 | 3D 미로드, 서버 SVG | **채택** |
| B. Commit Trace | hero 전체의 경로 타임라인 | 축약 다이어그램 | 발견보다 출처 설명에 치우치고 구현 부담이 큼 |
| C. Console Only | 없음 | 그대로 | 부담은 작지만 첫인상 목표 미달. 2단 목록만 가져옴 |

- 판 스택 높이는 칩의 개수와 같은 실제 값이다(`plates()`, 로그 스케일). 케이블은 장식이고 아티팩트 간 관계를 뜻하지 않는다.
- 제거: Canvas 2D universe, Latest read 카드(첫 행과 중복), 포인터 조명과 틸트, 글래스, 메시 빛, 그라디언트.

## 2. R3F를 다시 채택한 근거

Phase 74는 페이지에 +232.5 KB가 붙는 비용 때문에 R3F를 거부했다. 이번에는 별도 청크로 분리해, 넓은 화면·모션 허용·WebGL 있음·data-saver 아님일 때만 첫 페인트 뒤에 받는다. 나머지 경우에는 같은 도형의 서버 SVG가 남는다.

`frameloop="demand"`이므로 진입 1.5초와 사용자 반응 때만 그린다. 그래서 일시정지 컨트롤이 필요 없다(WCAG 2.2.2).

## 3. 측정 (FACT)

환경: 로컬 production standalone 빌드 2개, 같은 시드 DB(251행), headless Chromium, SwiftShader, 네트워크 제한 없음, cold context 5회 중앙값.

| 지표 | 1440 전 | 1440 후 | 390 4xCPU 전 | 390 4xCPU 후 |
|---|---|---|---|---|
| FCP / LCP (ms) | 72 / 72 | 60 / 60 | 112 / 112 | 112 / 112 |
| CLS | 0 | 0 | 0 | 0 |
| TBT (ms) | 0 | 0 | 39 | 30 |
| 홈 JS 전송량 (bytes) | 141,366 | 383,068 | 141,366 | 138,465 |
| 유휴 메인 스레드 (%) | 5.5 | 0.0 | 7.5 | 0.0 |

- 3D 청크: gzip 244,603 B(raw 923,538 B). 1440에서 `data-scene=live`까지 914 ms.
- CSS: gzip 10,979 → 9,089 B.
- 목록·상세 JS: 137,960 → 137,605 B, 138,861 → 138,506 B.
- 상세 CLS(1440): 0.0445 → 0.0008.

한계: 값은 이 머신의 상대 비교다. SwiftShader는 소프트웨어 렌더러라 GPU 비용을 실제와 다르게 보여 준다. 운영의 서버 응답(캡처 시 FCP 약 2–3초)은 이 측정에 포함되지 않는다.
